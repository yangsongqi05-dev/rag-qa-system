========== 锁：从零讲清楚 ==========

一、锁是什么
锁是用来解决并发冲突的机制。多个事务同时修改同一份数据时，如果没有锁，就会出现丢失更新、脏写等问题。
InnoDB 的锁按粒度分三级：全局锁、表级锁、行级锁。粒度越小，并发能力越强，但加锁的开销也越大。

二、全局锁
全局锁锁住整个数据库实例，让整个库处于只读状态。加锁命令是 flush tables with read lock;
它的典型用途是全库逻辑备份。加锁之后，其他线程的写操作和更新类事务都会被阻塞。
缺点是整个库都不能写，业务会停摆。所以 InnoDB 更推荐用 mysqldump 的 --single-transaction 参数，用一致性快照做备份，不用加全局锁。

三、表级锁
表锁：lock tables 表名 read 或者 write，这是显式加的表锁，整张表被锁住。
元数据锁（MDL）是 MySQL 5.5 引入的自动加锁，不需要显式声明。当一个事务访问某张表时，会自动加 MDL 读锁；当要修改表结构也就是 alter table 时，加 MDL 写锁。

MDL 最典型的坑是：一个长事务持有某张表的 MDL 读锁不放，之后来个 alter table 想加写锁就得等，而写锁在等待期间会阻塞后面所有对这个表的访问，导致整张表卡死。所以线上做 DDL 一定要先确认没有长事务。

四、行级锁
行锁是 InnoDB 的默认行为，也是它比 MyISAM 强的地方。
行锁按功能分两类：共享锁和排他锁。
共享锁又叫 S 锁、读锁。多个事务可以同时持有同一行的 S 锁，互不阻塞。加锁语法是 select ... lock in share mode;
排他锁又叫 X 锁、写锁。一行上只能有一个事务持有 X 锁，而且它和任何其他锁都互斥。加锁语法是 select ... for update;

和写操作的关系：update、delete、insert 会自动给涉及的行加 X 锁；普通 select 不加锁，靠 MVCC 读快照。

五、意向锁
意向锁是一种表级锁，作用是快速判断表里有没有行被锁住。
假设事务 A 锁住了表里的某一行，事务 B 想给整张表加表锁。如果没有意向锁，B 必须逐行检查有没有被锁住，效率极低。有了意向锁，A 在锁行之前会先在表上加一个意向锁标记，B 一看表上有意向锁就知道有行被锁了，不用逐行查。

意向锁分两种：意向共享锁 IS 和意向排他锁 IX。意向锁之间互不冲突，它只和表级的 S 锁、X 锁冲突。

六、记录锁、间隙锁、临键锁
这三种是行锁在 InnoDB 里的具体实现形式，只在可重复读级别下有完整的行为。
记录锁（Record Lock）：锁住索引上的一条具体记录。比如 where id = 5 并且 id 是唯一索引，就只锁第 5 行。
间隙锁（Gap Lock）：锁住两条记录之间的空隙，不包含记录本身。它的唯一目的是防止其他事务在这个空隙里插入新数据，从而避免幻读。间隙锁之间不冲突，两个事务可以同时持有同一个间隙的锁。

临键锁（Next-Key Lock）：记录锁加间隙锁的组合，锁住一个左开右闭的区间。比如锁住 5 到 10 这个区间，意思是 5 之后到 10 为止，包含 10 这条记录。InnoDB 默认用的就是临键锁。
为什么默认用临键锁？因为它既能锁住现有记录不被修改，又能锁住间隙不被插入，一举两得。

七、加锁的基本规则
规则一：加锁的对象是索引，不是行。如果查询没有用上索引，InnoDB 只能扫全表并锁住扫过的所有记录，表现上就像锁了整张表。这是最危险的情况，也是没索引导致锁表这句话的真正含义。
规则二：唯一索引等值查询命中记录时，临键锁会退化成记录锁。因为唯一索引保证了只有一个值匹配，不需要锁间隙。

规则三：唯一索引等值查询没命中记录时，临键锁会退化成间隙锁，锁住那个值所在的空隙。
规则四：非唯一索引等值查询时，会锁住匹配记录本身再加上前后的间隙。

八、死锁
死锁是指两个或多个事务互相持有对方需要的锁，又都在等对方释放，形成循环等待。
最典型的例子：事务 A 先锁了第 1 行，再去锁第 2 行；事务 B 先锁了第 2 行，再去锁第 1 行。两边都在等对方，谁也走不下去。
InnoDB 有死锁检测机制，发现死锁后会主动回滚其中一个事务，通常是修改行数少的那个，让另一个继续执行，并报一个 Deadlock found 的错误。

减少死锁的常见做法：一是让所有事务按同样的顺序访问数据，比如都按 id 从小到大更新，这样就不会形成循环等待；二是缩短事务长度，别让事务抱着锁等网络；三是给查询条件加索引，避免锁住大量行。
也可以打开死锁日志：set global innodb_print_all_deadlocks = on; 之后死锁信息会写进错误日志，用来分析。

九、常见问答
问：InnoDB 什么时候加行锁？答：update、delete、insert 会自动加排他锁；select 默认不加锁，除非显式写 for update 或 lock in share mode。
问：为什么说没索引会锁表？答：因为 InnoDB 加锁的对象是索引。如果查询条件用不上索引，InnoDB 只能全表扫描，扫描过程中遇到的每一行都会被锁住，效果上就等于锁了整张表。

问：间隙锁有什么用？答：防止其他事务在两条记录之间插入新数据，从而避免幻读。它只在可重复读隔离级别下生效。
问：为什么间隙锁之间不冲突？答：因为间隙锁的作用是阻止插入，它不需要和其他间隙锁互斥。两个事务可以同时持有同一个间隙的锁，但都不能在这个间隙里插入。
问：读已提交级别有间隙锁吗？答：没有。MySQL 在读已提交级别下会关闭间隙锁，只保留记录锁。所以读已提交的并发性能更好，但需要自己处理幻读问题。

问：怎么排查死锁？答：先执行 show engine innodb status，在 LATEST DETECTED DEADLOCK 那一段能看到最近一次死锁的两个事务分别持有什么锁、在等什么锁。也可以打开 innodb_print_all_deadlocks 把所有死锁记录到错误日志。
