========== 事务：从零讲清楚 ==========

一、事务是什么
事务是一组要么全部成功、要么全部失败的数据库操作。它把多条 SQL 绑成一个整体，中途任何一步出错，前面已经做的改动都要撤销。
最经典的例子是转账。A 给 B 转 100 元，需要两步：A 的账户减 100，B 的账户加 100。这两步必须一起成功或者一起失败，绝不能出现"A 减了但 B 没加"的情况，否则钱就凭空消失了。

事务用三条语句控制：begin（或 start transaction）开启事务，commit 提交，rollback 回滚。提交之后改动才真正生效。

二、ACID 四大特性
原子性（Atomicity）：事务里的操作是一个不可分割的整体，要么全做，要么全不做。转账例子里，两步必须绑定。
一致性（Consistency）：事务执行前后，数据都必须满足业务规则。比如转账前后，两个账户的总额必须不变。一致性是目的，其他三个特性是手段。
隔离性（Isolation）：多个事务并发执行时，互相之间不能看到对方未提交的中间状态。隔离性解决的是并发时的干扰问题。

持久性（Durability）：事务一旦提交，改动就是永久的，即使之后数据库宕机或断电也不会丢。
四个特性怎么实现的：原子性靠 undo log（回滚日志），持久性靠 redo log（重做日志），隔离性靠锁和 MVCC，一致性靠前面三个共同保证。

三、并发会带来三个问题
脏读：一个事务读到了另一个事务还没提交的数据。如果那个事务后来回滚了，读到的就是从未存在过的数据，所以叫脏读。
不可重复读：同一个事务里，两次读同一行，结果不一样。原因是两次读之间，另一个事务改了这行并提交了。
幻读：同一个事务里，两次执行同一个范围查询，第二次多出了几行或者少了几行。原因是两次查之间，另一个事务插入或删除了满足条件的行。

不可重复读和幻读的区别在于：不可重复读针对的是某一行的内容变了，幻读针对的是符合条件的结果集行数变了。

四、四种隔离级别
读未提交（Read Uncommitted）：最低的级别，一个事务能读到另一个事务未提交的数据。三个问题都可能发生，基本不用。
读已提交（Read Committed）：只能读到已提交的数据，解决了脏读。但不可重复读和幻读仍然存在。Oracle 和 PostgreSQL 的默认级别。

可重复读（Repeatable Read）：同一个事务里多次读同一行，结果始终一致，解决了脏读和不可重复读。这是 MySQL InnoDB 的默认级别。
串行化（Serializable）：最高的级别，事务串行执行，三个问题全解决，但并发性能最差。
隔离级别越高，数据越安全，并发性能越差。这是一个权衡。

五、可重复读是怎么实现的
InnoDB 在可重复读级别下，靠 MVCC（多版本并发控制）实现读的时候不加锁。
核心思路是：每次修改一行数据时，不是直接覆盖，而是把旧版本留下来，用一条版本链串起来。读的时候根据一个叫 Read View 的快照，决定能看到哪个版本。
undo log（回滚日志）负责保存旧版本。每次更新前，先把这一行的旧值写进 undo log，然后修改当前值，并让当前行的隐藏字段指向 undo log 里的旧版本。多个版本串起来就形成了版本链。

Read View 是事务开始时生成的一个快照，里面记录了当时还在活跃、也就是未提交的事务 ID 列表。读数据时按规则判断每个版本是否可见：如果某个版本的创建者事务在快照里还活跃着，说明那是未提交的改动，看不见，就顺着版本链往前找更老的版本。

六、读已提交和可重复读的差别在哪
差别在于生成 Read View 的时机。
读已提交：每次执行 select 都生成一个新的 Read View。所以同一个事务里两次查询能看到不同的结果，这就是不可重复读。
可重复读：只在第一次执行 select 时生成一个 Read View，之后整个事务都用这一个。所以同一个事务里怎么查都是一样的结果。

可重复读并不能完全避免幻读，但 InnoDB 用间隙锁做了补充。在可重复读级别下，普通 select 靠 MVCC 读快照，不会加锁也不会幻读；而带 for update 或 lock in share mode 的当前读会加间隙锁，堵住其他事务在这个区间插入新行，从而避免幻读。

七、当前读和快照读
快照读，也就是普通 select：读取的是 MVCC 生成的历史版本，不加锁。这是 InnoDB 高效并发的关键。
当前读：读取的是最新版本，并且会加锁。以下几种都属于当前读：select ... for update、select ... lock in share mode、update、delete、insert。

区分这两者很重要。日常的查询走快照读，并发能力强；一旦涉及修改或者显式加锁，就是当前读，会互相阻塞。

八、事务的隔离级别怎么设置
查看当前级别：select @@transaction_isolation;
设置会话级别，只影响当前连接：set session transaction isolation level repeatable read;
设置全局级别，影响之后的新连接：set global transaction isolation level read committed;

MySQL 8.0 里参数名是 transaction_isolation，5.7 及以前叫 tx_isolation。

九、常见问答
问：MySQL 默认的隔离级别是什么？答：InnoDB 默认是可重复读（Repeatable Read），这一点和 Oracle、PostgreSQL 不同，它们默认是读已提交。
问：为什么 MySQL 默认用可重复读？答：历史原因是早期 MySQL 的主从复制用 statement 格式记录 binlog，可重复读能保证主从数据一致。另外可重复读下配合间隙锁能避免幻读。

问：脏读和幻读的区别是什么？答：脏读是读到了别人未提交的数据；幻读是同一个事务里两次范围查询，结果集的行数变了。脏读是根本不该读到的数据，幻读是合法数据但数量变了。
问：MVCC 能解决幻读吗？答：不能完全解决。MVCC 保证快照读不幻读，但当前读如果不加间隙锁，仍然可能幻读。InnoDB 是靠间隙锁补上的。

问：读已提交级别下靠什么解决不可重复读？答：靠 MVCC。每次查询都生成新的 Read View，读到的都是查询这一刻已提交的最新版本，所以不会读到旧版本。但同一个事务里两次查会看到不同结果，这在读已提交下是正常的。
问：undo log 和 redo log 有什么区别？答：undo log 存旧值，用于回滚和 MVCC 读历史版本；redo log 存新值，用于崩溃恢复。undo 是逻辑日志，记录怎么撤销；redo 是物理日志，记录哪个页改了什么。
