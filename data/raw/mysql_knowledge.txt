一、四个心法（背下来，比记语法有用得多）
心法 1：SQL 的书写顺序和执行顺序不一样
SELECT → FROM → WHERE → GROUP BY → HAVING → ORDER BY → LIMIT
1. FROM        先确定从哪张表查
2. WHERE       过滤行（分组之前）
3. GROUP BY    分组

4. HAVING      过滤分组（分组之后）
5. SELECT      选出要显示的列
6. ORDER BY    排序
7. LIMIT       限制条数
提示  理解这个顺序，你就明白为什么 WHERE 里不能写聚合函数了 —— 因为 WHERE 执行的时候，还没分组，COUNT、AVG 这些根本还没算出来。

-- WHERE：先筛人，再统计
SELECT department_id, AVG(salary)
FROM employees

WHERE salary > 5000          -- 先把工资低于 5000 的人去掉
GROUP BY department_id;
-- HAVING：先统计，再筛结果
SELECT department_id, AVG(salary)
FROM employees
GROUP BY department_id

HAVING AVG(salary) > 10000;  -- 算出平均工资后再筛
提示  一句话记法：「分组前用 WHERE，分组后用 HAVING；聚合函数只能放 HAVING」。

二、九大模板（写 SQL 时照着套）

模板 1：基础查询
SELECT 字段1, 字段2, 字段3
FROM 表名;
-- 别名
SELECT last_name AS 姓, salary AS 工资 FROM employees;
-- 去重
SELECT DISTINCT department_id FROM employees;
-- 拼接
SELECT CONCAT(last_name, '_', first_name) AS 姓名 FROM employees;

▪  例题：查询所有员工的姓名和年薪（年薪 = 月薪 × 12 × (1 + 奖金率)，没有奖金的按 0 算）
SELECT last_name, salary * 12 * (1 + IFNULL(commission_pct, 0)) AS 年薪
FROM employees;
提示  没有奖金的人 `commission_pct` 是 NULL，NULL 参与运算结果还是 NULL。所以必须用 `IFNULL(字段, 0)` 换成 0。这是必考点。

▪  例题 1：查询工资大于 12000 的员工的姓名和工资
SELECT last_name, salary FROM employees WHERE salary > 12000;
▪  例题 2：查询没有奖金的员工姓名（两种写法）
SELECT last_name FROM employees WHERE commission_pct IS NULL;

SELECT last_name FROM employees WHERE commission_pct <=> NULL;
提示  `IS NULL` 和 `= NULL` 不一样！`= NULL` 永远查不出东西，这是新手必踩的坑。

模板 3：排序
SELECT 字段
FROM 表名
WHERE 条件
ORDER BY 字段1 ASC|DESC, 字段2 ASC|DESC;
▪  ASC 是升序（默认，可省略），DESC 是降序
▪  多个字段排序：先按第一个字段排，第一个字段相同的再按第二个排
▪  ORDER BY 后面可以写：字段名、别名、表达式、函数

▪  例题：按工资降序显示员工姓名和工资，工资相同的按入职时间升序
SELECT last_name, salary, hiredate
FROM employees
ORDER BY salary DESC, hiredate ASC;

SELECT 分组字段, 聚合函数(字段)
FROM 表名
WHERE 分组前的条件
GROUP BY 分组字段
HAVING 分组后的条件
ORDER BY 排序字段
LIMIT 条数;

只对数值型有效

只对数值型有效

最大值

提示  聚合函数全部忽略 NULL。 所以 `COUNT(*)` 和 `COUNT(字段)` 结果可能不一样 —— 后者不统计 NULL 行。这个细节面试爱问。
▪  例题 1：查询每个工种的最高工资
SELECT job_id, MAX(salary) AS 最高工资

FROM employees
GROUP BY job_id;
▪  例题 2：查询每个部门的平均工资，只显示平均工资大于 10000 的部门
SELECT department_id, AVG(salary) AS 平均工资
FROM employees
GROUP BY department_id
HAVING AVG(salary) > 10000;

▪  例题 3：查询有奖金的员工中，每个部门的最高工资，只显示最高工资大于 12000 的，按最高工资降序
SELECT department_id, MAX(salary) AS 最高工资
FROM employees
WHERE commission_pct IS NOT NULL
GROUP BY department_id

HAVING MAX(salary) > 12000
ORDER BY 最高工资 DESC;
提示  这道题同时用了 WHERE、GROUP BY、HAVING、ORDER BY，是最典型的「全套」写法。能把这道题默写出来，分组查询就过关了。

模板 5：连接查询
-- 内连接：两边都匹配得上
SELECT 字段
FROM 表1 AS 别名1
INNER JOIN 表2 AS 别名2 ON 别名1.字段 = 别名2.字段
WHERE 条件
GROUP BY ...
ORDER BY ...;
-- 左外连接：左表全要
SELECT 字段
FROM 表1 AS 别名1

LEFT JOIN 表2 AS 别名2 ON 别名1.字段 = 别名2.字段
WHERE 别名2.主键 IS NULL;    -- 这一行是查「没有匹配」的关键
▪  连接条件用 `ON`，过滤条件用 `WHERE`，两个不要混
▪  三张表就再写一个 `INNER JOIN`，往下接
▪  例题 1：查询员工姓名和对应的部门名

SELECT e.last_name, d.department_name
FROM employees AS e
INNER JOIN departments AS d ON e.department_id = d.department_id;
▪  例题 2：查询每个城市的部门个数
SELECT l.city, COUNT(*) AS 部门个数

FROM departments AS d
INNER JOIN locations AS l ON d.location_id = l.location_id
GROUP BY l.city;
▪  例题 3：查询员工姓名和他上级的姓名（自连接）
SELECT e.last_name AS 员工, m.last_name AS 上级

FROM employees AS e
INNER JOIN employees AS m ON e.manager_id = m.employee_id;
▪  例题 4：查询哪个部门没有员工
SELECT d.department_name
FROM departments AS d
LEFT JOIN employees AS e ON d.department_id = e.department_id

WHERE e.employee_id IS NULL;
提示  自连接的关键：同一张表起两个不同的别名，当成两张表用。上面例题 3 里，`e` 是员工，`m` 是上级。

模板 6：子查询
-- 位置一：WHERE 后面（最常用）
SELECT 字段 FROM 表 WHERE 字段 = (SELECT ...);
-- 位置二：FROM 后面（当临时表）
SELECT * FROM (SELECT ...) AS 别名 WHERE ...;
-- 位置三：SELECT 后面（只能出单个值）

SELECT 字段, (SELECT ...) AS 新列 FROM 表;
-- 位置四：EXISTS 后面（相关子查询）
SELECT 字段 FROM 表1 WHERE EXISTS (SELECT * FROM 表2 WHERE 表2.字段 = 表1.字段);
▪  例题 1：查询工资比 Abel 高的员工

SELECT last_name, salary
FROM employees
WHERE salary > (SELECT salary FROM employees WHERE last_name = 'Abel');
▪  例题 2：查询工资高于本部门平均工资的员工（相关子查询）
SELECT last_name, salary, department_id

FROM employees AS e
WHERE salary > (
SELECT AVG(salary) FROM employees WHERE department_id = e.department_id
);
▪  例题 3：查询每个部门工资最高的员工姓名和工资（这道是重点题）
-- 写法一：相关子查询

SELECT last_name, salary, department_id
FROM employees AS e
WHERE salary = (
SELECT MAX(salary) FROM employees WHERE department_id = e.department_id
);
-- 写法二：派生表 + 连回去

SELECT e.last_name, e.salary, e.department_id, e.department_id
FROM employees AS e
INNER JOIN (
SELECT department_id, MAX(salary) AS max_sal
FROM employees

GROUP BY department_id
) AS t
ON e.department_id = t.department_id AND e.salary = t.max_sal;
提示  「相关子查询」的特征：子查询里用到了外层的字段（上面 `e.department_id`）。子查询会对外层的每一行各执行一次。

模板 7：分页与联合查询
-- 分页：从第 offset 条开始，取 size 条（offset 从 0 开始数）
SELECT * FROM 表 LIMIT offset, size;
-- 每页 size 条，取第 n 页：
-- LIMIT (n-1) * size, size
-- 联合查询：把多条查询结果上下拼起来

SELECT ... FROM 表1 WHERE ...
UNION
SELECT ... FROM 表2 WHERE ...;
▪  UNION 要求两条语句的列数一致、类型顺序一致
▪  UNION 会自动去重，UNION ALL 不去重（更快）
▪  例题：每页显示 10 条，查询第 3 页
SELECT * FROM employees LIMIT 20, 10;   -- 跳过前 20 条，取 10 条

模板 8：增删改（DML）
-- 增：指定列（推荐）
INSERT INTO 表名(列1, 列2) VALUES(值1, 值2);
INSERT INTO 表名(列1, 列2) VALUES(值1, 值2), (值3, 值4);   -- 批量
-- 增：把查询结果插进去（建表时常用）
INSERT INTO 表名(列1, 列2) SELECT 列1, 列2 FROM 另一张表;

-- 改
UPDATE 表名 SET 列1 = 值1, 列2 = 值2 WHERE 条件;
-- 删
DELETE FROM 表名 WHERE 条件;
TRUNCATE TABLE 表名;          -- 清空整表
提示  两条铁律： ① UPDATE 和 DELETE 忘写 WHERE 会改/删全表。② 先 SELECT 确认范围，再改成 UPDATE 或 DELETE。

模板 9：建表与改表（DDL）
-- 建库
CREATE DATABASE IF NOT EXISTS 库名;
DROP DATABASE IF EXISTS 库名;
-- 建表（带约束，实际工作必须这么写）
CREATE TABLE 表名(
id         INT PRIMARY KEY AUTO_INCREMENT,     -- 主键 + 自增

name       VARCHAR(20) NOT NULL,               -- 非空
age        INT DEFAULT 0,                      -- 默认值
phone      VARCHAR(11) UNIQUE,                 -- 唯一

created_at DATETIME DEFAULT CURRENT_TIMESTAMP  -- 默认当前时间
);
-- 改表
ALTER TABLE 表名 ADD COLUMN 新列 类型;                 -- 加列
ALTER TABLE 表名 MODIFY COLUMN 列名 新类型;            -- 改类型

ALTER TABLE 表名 CHANGE COLUMN 旧名 新名 类型;         -- 改列名
ALTER TABLE 表名 DROP COLUMN 列名;                     -- 删列
ALTER TABLE 表名 RENAME TO 新表名;                     -- 改表名

-- 删表
DROP TABLE IF EXISTS 表名;
▪  常用数据类型：INT（整数）、VARCHAR(n)（变长字符串）、TEXT（长文本）、DECIMAL(m,n)（精确小数，钱用它）、DATETIME（日期时间）
▪  表的复制三招
CREATE TABLE 新表 LIKE 旧表;                     -- 只复制结构

CREATE TABLE 新表 SELECT * FROM 旧表;              -- 结构 + 全部数据
CREATE TABLE 新表 SELECT id, name FROM 旧表
WHERE 条件;                                      -- 结构 + 部分数据

三、错题本：你在自己练习里写错的 6 个地方
错误 1：全角分号
SELECT 100 % 98 AS 结果；      ← 结尾是全角「；」，MySQL 不认
SELECT 100 % 98 AS 结果;       ← 必须是半角「;」
提示  中文输入法下打标点最容易出这个错。写 SQL 时把输入法切到英文。

错误 2：SELECT 后面多一个逗号
SELECT last_name, FROM employees WHERE ...    ← 错
SELECT last_name FROM employees WHERE ...      ← 对
错误 3：字段名拼错
WHERE m.employee_id = e.employees_id     ← 错，表里没有 employees_id 这个字段

WHERE m.employee_id = e.employee_id      ← 对
错误 4：用反引号包字符串
WHERE bo.`boyName` = `张无忌`     ← 错，反引号是包「字段名」的
WHERE bo.`boyName` = '张无忌'      ← 对，字符串用单引号
提示  这是最要紧的一个，面试里会被抓。记住：反引号包字段名和表名，单引号包字符串和日期。

错误 5：CROSS JOIN 的写法
FROM beauty.b, CROSS join boys.bo;     ← 错
FROM beauty b CROSS JOIN boys bo;      ← 对
错误 6：建表不带约束
-- 课程示例的写法（学习用可以，实际工作不行）
CREATE TABLE book(id INT, bname VARCHAR(20), price DOUBLE);

-- 自己建表要这么写
CREATE TABLE book(
id    INT PRIMARY KEY AUTO_INCREMENT,
bname VARCHAR(20) NOT NULL,
price DECIMAL(10,2) DEFAULT 0
);
提示  没有主键的表，数据没办法定位，也没办法和别人关联。建表第一件事就是定主键。

五、面试会问的 8 个问题
●  1　WHERE 和 HAVING 有什么区别？ 答：WHERE 在分组前过滤行，HAVING 在分组后过滤分组结果；WHERE 里不能写聚合函数。
●  2　COUNT(*) 和 COUNT(字段) 有什么区别？ 答：COUNT(*) 统计所有行；COUNT(字段) 不统计该字段为 NULL 的行，所以结果可能更小。

●  3　INNER JOIN 和 LEFT JOIN 有什么区别？ 答：内连接只返回两边都匹配的记录；左连接保留左表全部记录，右表没匹配的字段显示 NULL。查「没有 XX 的 YY」用左连接加 IS NULL。
●  4　DELETE、TRUNCATE、DROP 有什么区别？ 答：DELETE 按条件删数据，可以带 WHERE，自增值接着走；TRUNCATE 清空整表，不能带 WHERE，自增值重置为 1，效率更高；DROP 是把整张表结构一起删掉。

●  5　子查询和连接查询有什么区别？哪个性能更好？ 答：子查询可读性好，适合「先算一个结果再拿它去查」；连接查询通常性能更好，尤其是有索引的时候。实际开发里能用连接就用连接。
●  6　什么是相关子查询？ 答：子查询里引用了外层查询的字段，外层每一行都会执行一次子查询，所以性能较差。
●  7　UNION 和 UNION ALL 有什么区别？ 答：UNION 会去重，UNION ALL 不去重但更快。知道不会重复时用 UNION ALL。

●  8　没有索引的话，查询会怎么样？ 答：会全表扫描，数据量大时非常慢。索引相当于书的目录。（这部分现在不用深入，面试前一周再补）

SELECT DISTINCT department_id FROM employees;
▪  DISTINCT 只能放在所有字段的最前面，后面跟一个字段
▪  易错：SELECT department_id, DISTINCT job_id 是错的

二、+ 号的作用（重要）
MySQL 里 + 号只做运算，不做拼接
情况
结果
两个数字相加
SELECT 100+1; → 101
数字 + 字符（能转数字）
SELECT 100+'1'; → 101
数字 + 字符（不能转）
SELECT 100+'abc'; → 100（字符当 0）
任一方为 NULL
结果为 NULL

提示  面试常问：MySQL 里怎么拼接字符串？答案是 CONCAT()，不是 + 号。
拼接字符串用 CONCAT
SELECT CONCAT(1, 2, 3);                      -- 结果 123
SELECT CONCAT(last_name, '_', first_name) AS 姓名

FROM employees;
▪  易错：CONCAT 里只要有一个参数是 NULL，整个结果就是 NULL
▪  解决办法：用 IFNULL(字段, 替代值) 包一层
SELECT CONCAT(last_name, '_', IFNULL(commission_pct, 0)) FROM employees;

三、条件查询
语法
SELECT 查询列表 FROM 表名 WHERE 筛选条件;
① 条件表达式
SELECT * FROM employees WHERE salary > 12000;
SELECT last_name, department_id FROM employees
WHERE department_id != 90;         -- != 等价于 <>

② 逻辑表达式（AND / OR / NOT）
SELECT last_name, salary, commission_pct
FROM employees
WHERE salary >= 10000 AND salary <= 20000;
SELECT * FROM employees
WHERE department_id < 90 OR department_id > 110 OR salary > 15000;

▪  易错：AND 的优先级高于 OR，混用时一定加括号
-- 想要的是：部门 90 且工资 >20000，或者部门 80
-- 错误写法（实际含义不同）
WHERE department_id = 90 OR department_id = 80 AND salary > 20000
-- 正确写法
WHERE department_id = 90 OR (department_id = 80 AND salary > 20000)

③ 模糊查询 LIKE
SELECT * FROM employees WHERE last_name LIKE '%a%';
通配符
含义
%
任意多个字符（包括 0 个）
_
任意单个字符
-- 名字第三个字符是 n，第五个是 l
SELECT last_name, salary FROM employees
WHERE last_name LIKE '__n_l%';

转义字符
-- 正常匹配：名字第二个字符是 _
SELECT last_name FROM employees
WHERE last_name LIKE '__\_%';
▪  易错：要查 "_" 本身，必须用反斜杠转义成 \_，否则 _ 会被当成通配符
④ BETWEEN AND
SELECT * FROM employees

WHERE employee_id BETWEEN 100 AND 120;
▪  注意：包含两个端点（100 和 120 都算）
▪  两个值不能颠倒，BETWEEN 100 AND 120 不能写成 120 AND 100
⑤ IN
SELECT last_name, job_id FROM employees

WHERE job_id IN ('IT_PROT', 'AD_VP');
▪  等价于 job_id = 'IT_PROT' OR job_id = 'AD_VP'
▪  IN 列表里不支持通配符，写 '%IT%' 没用，那种情况要用 LIKE
⑥ IS NULL / IS NOT NULL
SELECT last_name, commission_pct FROM employees

WHERE commission_pct IS NULL;
▪  易错：不能写 = NULL，因为 NULL 不等于任何值（包括它自己）
▪  判断空值只能用 IS NULL 或 IS NOT NULL
⑦ 安全等于 &lt;=&gt;
-- 能判断 NULL（= 做不到）
SELECT last_name, commission_pct FROM employees

WHERE commission_pct &lt;=&gt; NULL;
-- 也能判断普通值
SELECT last_name, salary FROM employees
WHERE salary &lt;=&gt; 12000;
运算符
能否判断 NULL
可读性
=
不能
好
&lt;=&gt;
能
差
提示  实际工作中判断 NULL 还是用 IS NULL，可读性更好。&lt;=&gt; 知道有这个功能就行。

四、排序查询
语法
SELECT 查询列表
FROM 表名
WHERE 筛选条件
ORDER BY 排序字段 [ASC|DESC];
▪  ASC 升序（默认，可省略），DESC 降序
四种排序场景
-- ① 基本排序
SELECT * FROM employees ORDER BY salary ASC;
SELECT * FROM employees ORDER BY salary DESC;

-- ② 排序 + 筛选（WHERE 写在 ORDER BY 前面）
SELECT * FROM employees
WHERE department_id >= 90
ORDER BY hiredate ASC;
-- ③ 按表达式排序
SELECT *, salary * 12 * (1 + IFNULL(commission_pct, 0)) AS 年薪

FROM employees
ORDER BY salary * 12 * (1 + IFNULL(commission_pct, 0)) DESC;
-- ④ 按别名排序（更简洁）
SELECT *, salary * 12 * (1 + IFNULL(commission_pct, 0)) AS 年薪

FROM employees
ORDER BY 年薪 DESC;
-- ⑤ 按函数排序
SELECT LENGTH(last_name) AS 字节长度, last_name, salary
FROM employees
ORDER BY 字节长度 DESC;
-- ⑥ 多字段排序（先按工资升序，工资相同再按编号降序）

SELECT * FROM employees
ORDER BY salary ASC, employee_id DESC;
▪  易错：WHERE 必须写在 ORDER BY 之前，顺序颠倒会报错
▪  易错：ORDER BY 后面可以用别名（MySQL 特性），但 WHERE 里不能用别名

六、你笔记里的语法问题（建议修正）
1. 用了中文分号
-- 你的原文

▪  中文分号不是合法的 SQL 字符，会报 1064 错误，改成英文 ;
2. 少了一个逗号
-- 你的原文（报错）
SELECT last_name, FROM employees WHERE last_name LIKE '__\_%';

▪  last_name 后面多了一个逗号，去掉即可
SELECT last_name FROM employees WHERE last_name LIKE '__\_%';
3. SELECT 和 FROM 之间少了星号
-- 你的原文（报错）
SELECT * FROM employees ORDER BY salary ASC;

▪  这行其实是对的。真正有问题的是下面这条：
-- 缺少要查询的字段
SELECT FROM employees WHERE salary > 12000;    -- 错
SELECT * FROM employees WHERE salary > 12000;  -- 对
4. WHERE 位置错误
-- 你的原文（报错）

SELECT last_name, DATE_FORMAT(hiredate,'%y年%m月%d日')
FROM employees;
WHERE commission_pct IS NOT NULL;
▪  WHERE 属于同一条语句，不能加分号断开
SELECT last_name, DATE_FORMAT(hiredate, '%y年%m月%d日')

FROM employees
WHERE commission_pct IS NOT NULL;
5. 结尾加分号的习惯
▪  每一条 SQL 语句都以英文分号结尾
▪  就算是单条语句，也建议加上，避免多条语句连在一起时出错

10. JOIN 关联查询
-- INNER JOIN：只查两边都匹配的（最常用）
SELECT u.name, o.product, o.amount
FROM orders o
INNER JOIN users u ON o.user_id = u.id;

FROM users u
LEFT JOIN orders o ON u.id = o.user_id;

#二、sql99 语法
/*
语法：
select 查询列表
from 表 1 别名 【连接类型】
join 表 2 别名
on 连接条件
【where 筛选条件】
【group by 分组】
【having 筛选条件】
【order by 排序列表】

分类：
内连接（★）：inner
外连接
左外 (★):left 【outer】
右外 (★)：right 【outer】
全外：full【outer】
交叉连接：cross
*/
#一）内连接
/*
语法：
SELECT 查询列表
FROM 表1 别名
inner join 表2 别名
on 连接条件
分类
等值
非等值
自连接
*/

#1.等值连接
#查询员工名，部门名
SELECT last_name,department_name
FROM employees as e
INNER JOIN departments as d
on e.`department_id`=d.`department_id`;
#查询名字中包含e的员工名和工种名

SELECT last_name,job_title
FROM employees as e
INNER JOIN jobs as j
on e.`job_id`=j.`job_id`
WHERE e.`last_name` like '%e%';
#查询部门个数>3的城市名和部门个数
SELECT city,count(*) as 部门个数

FROM departments as d
INNER JOIN locations as l
on d.`location_id`=l.`location_id`
GROUP BY city
HAVING count(*)>3;
#查询部门员工个数>3的部门名和员工个数，并按个数降序
SELECT COUNt(*),department_name

FROM employees as e
INNER JOIN departments as d
on e.`department_id`=d.`department_id`
GROUP BY department_name
HAVING COUNT(*)>3
ORDER BY count(*)
#查询员工名，部门名，工种名，并按部门名降序()

SELECT last_name,department_name,job_title
FROM employees as e
INNER JOIN departments as d
on e.`department_id`=d.`department_id`
INNER JOIN jobs j
on e.`job_id`=j.`job_id`

ORDER BY department_name desc;
#二)非等值连接
#查询工资级别
SELECT salary,grade_level
FROM employees as e
JOIN job_grades as g
on e.`salary` BETWEEN g.`lowest_sal` AND g.`highest_sal`;

#三）自连接
#查询员工，上级名字
SELECT e.last_name,m.last_name
FROM employees as e
JOIN employees as m
on e.`manager_id`=m.`employee_id`
#二.外连接
/*
应用查询：一个表中一另一个表没有
特点：
1、外连接的查询结果为主表中的所有记录

如果从表中有和它匹配的，则显示匹配的值
如果从表中没有和它匹配的，则显示 null
外连接查询结果 = 内连接结果 + 主表中有而从表没有的记录
2、左外连接，left join 左边的是主表
右外连接，right join 右边的是主表
3、左外和右外交换两个表的顺序，可以实现同样的效果
*/
#查询男朋友 不在男神表的女神名

#左外
SELECT b.name
FROM beauty as b
LEFT OUTER join boys as bo
on b.`boyfriend_id`=bo.`id`
WHERE bo.`id` is null;
#查询哪个部门没有员工
SELECT d.*,e.employee_id
FROM departments as d

LEFT OUTER join employees as e
on d.`department_id`=e.`department_id`
WHERE e.`employee_id` is null
#全外
#交叉连接
SELECT b.*,bo.*
FROM beauty.b,
CROSS join boys.bo;
