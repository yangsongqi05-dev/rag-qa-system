系统说明

架构分层、技术栈、数据流向与关键设计决策

一、系统架构（五层）

层次职责对应模块
第 5 层　Web 层对外提供 HTTP 接口与页面api/main.py、web/
第 4 层　Agent 层自主判断调用哪个知识库（规划中）agent/
第 3 层　检索层切块 → 向量化 → 余弦检索 → 重排序core/
第 2 层　数据层向量库文件、MySQL 问答历史data/、db/
第 1 层　模型层向量化模型、生成模型、重排序模型llm/、core/embedder.py

二、技术栈

语言与框架Python 3.11、FastAPI、SQLAlchemy、MySQL 8.0
向量化模型BAAI/bge-m3（输出 1024 维向量）
生成模型deepseek-ai/DeepSeek-V3
重排序模型BAAI/bge-reranker-v2-m3
检索实现手写余弦相似度、手写 BM25（字符二元组分词）、RRF 融合
前端原生 HTML / CSS / JavaScript（无框架）

三、数据流向

建库阶段（离线执行一次）
语料 txt → 读取 → 按空行切块（385 块 → 合并后 377 块）→ 逐块向量化 → 存入 vector.json

问答阶段（每次提问执行）
提问 → 转向量 → 与库中 377 个向量逐个计算余弦相似度 → 取 top10 →
rerank 精排取 top3 → 组装提示词（规则 + 资料 + 问题）→ DeepSeek 生成 →
返回答案与引用出处 → 写入 MySQL 问答历史

四、关键设计决策

决策依据
检索层手写而非调用框架 为了完全掌握每一步的实现细节；同时保留手写版本作为实验基线，便于与框架方案对比。
按空行切块而非固定长度 固定长度会把一句话或一段代码从中间切断；按空行切能保证每块语义完整。实测块长中位数 168 字。
采用两阶段检索（粗筛 + 精排） 向量检索让问题与文档“各自算分”，判别力有限；rerank 同时看到问题与候选原文，判别力更高但速度慢，因此只用于精排。实测命中率 73% → 87%。
防幻觉以提示词为主、阈值为辅 阈值的有效性依赖语料特性：游戏百科语料上域外得分（0.605）甚至超过域内（0.593），阈值失效；专业技术语料上才有清晰空档。而提示词约束在任何语料上都能生效。
不使用向量数据库，用 JSON 文件 当前规模仅 377 块，暴力遍历耗时在毫秒级；数据量到十万级再引入 Milvus 等带索引的向量库更合适。
